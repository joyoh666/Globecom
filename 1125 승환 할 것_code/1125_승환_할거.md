## A. 오늘 — 빔 없이 (A1~A3 은 승환이 먼저 혼자 해 보고, 막히거나 이상하면 윤태에게 물어본다)

### A1. 로봇 위치 오차 실측 (승환 혼자, 막히면 윤태에게 질문) ★ 오늘의 핵심

**왜**: 빔 각도를 로봇 위치(Create3 odometry = 바퀴 회전 + IMU)로 계산한다. 위치가 틀리면 빔이 엉뚱한 데를 본다.
**기준**: 빔 반폭 12.5° (빔폭 25~30° 의 반). 각도 오차가 그 1/3(약 4°) 안이면 OK.

준비물: 바닥 테이프 · 줄자 · (있으면) 각도기 · 로봇 PC (ROS2, turtlebot4 bringup 켜진 상태)

1. 바닥에 **출발 자리(로봇 가운데)** 와 **+x 방향(로봇이 처음 보는 쪽)** 을 테이프로 표시. 줄자 점 4개를 미리 붙인다: (1,0) · (1,1) · (0,1) · (0,0) [m, y 는 왼쪽 +]
2. 점 찍기 — 로봇을 텔레옵이나 손으로 점마다 옮기며 Enter, 줄자 값 입력
   ```bash
   python -m tools.odom_check manual --points "1,0 1,1 0,1 0,0"
   ```
3. 데모 이동 그대로 — 60 s facing 이동 뒤 멈춘 자리를 줄자로 (출발 표시 기준 앞+/뒤−, 왼쪽+/오른쪽−)
   ```bash
   python -m tools.odom_check facing --duration 60 --seed 72
   ```
   2~3번 반복 (seed 72 · 1 · 2) 하면 좋다
4. **실험 기록지** (`1125_실험기록지_빈칸.docx`, 한 장) — 결과로 꼭 남길 것만 적는다
   1 RU 위치 (x, y) · 2 로봇 위치 오차 (run 마다 화면 마지막 줄의 최대 위치 오차 cm · 최대 빔 각도 오차 °, 판정은 윤태가) · 3 2.2 GHz 시험 (X310 IP · CSI 들어옴 · 로봇 움직임 · 저장 폴더 · 에러) · 4 각도 GRU ([TEST] 줄의 +25 / +125 ms 숫자) · 5 메모 · 질문
   2번 표는 손으로 적어도 되고, `python tools/exp_record.py --date 20261125` 를 돌리면 2번이 채워진 기록지가 `logs/20261125_실험기록지.docx` 로 나온다 (python-docx 필요)
5. 윤태에게 보낼 것: **실험 기록지 한 장**

그림만 따로 보거나 RU 자리를 바꿔 다시 계산할 때:
```bash
python tools/odom_plot.py logs/odom_check_YYYYmmdd_HHMMSS.json
python -m tools.odom_check analyze logs/odom_check_*.json --config <RU 자리를 고친 json>
```

볼 것: 최대 위치 오차 [cm] · 최대 방향(yaw) 오차 [°] · 최대 빔 각도 오차 [°] 와 판정 (OK / 주의 / 문제)
⚠ 지금 런타임은 dock 을 건너뛴다 — 매 run 원점 = 출발 자리, 오차는 run 안에서만 쌓인다. 그래서 60 s run 의 끝 오차가 실제 데모 조건이다

### A2. 2.2 GHz 실기 시험 준비 (장비 오기 전 남은 것, 승환 혼자, 막히면 질문)

- X310 3대 IP 확정 → `MOTION=facing` 실기 시험 (`code/README.md` '실행' 절)
- **RU 3개 자리를 줄자로 대략 재서 (x, y) 상대좌표로 알려 주기** — 로봇 출발 자리 = (0, 0), 로봇 정면 = +x, 왼쪽 = +y (m). 정밀할 필요 없고 대략적인 세팅 수치면 된다. config(`geometry.rus`)에는 윤태가 넣는다. 지금 값은 가정이다
  → 이것이 있어야 A1 의 빔 각도 오차와 B3 의 각도 입력이 실제 기하가 된다
- 고정 빔 대비: RU 정면을 로봇 구역 가운데로

### A3. 각도 입력 GRU 코드 받아 읽기 (승환)

빔이 없어도 할 수 있는 것:
```bash
python tools/build_beam_dataset.py --logs <10-26 S66~S75 run 폴더들의 상위>   # → data_ready_beam/ (각도 = 로봇 위치에서 계산)
python train_GRU_beam.py                           # 각도 넣음
python train_GRU_beam.py --no-angle                # 같은 조건 기준 모델
python live_demo/live_dashboard.py --predictor-model checkpoints_beam/gru_angle_hold.pt   # + beam_tracker --dry-run 이 각도를 보냄
```
- 윤태가 돌린 결과 (10-26 데이터, test S72·S73, NMSE +25 / +125 ms): 각도 넣음 −20.0 / −6.7 dB · 없음 −20.3 / −7.3 dB → **빔 없는 데이터에선 이득 없음** (예상대로 — 각도가 위치 정보밖에 안 줌)
- 구조: 입력 = [CSI 토큰 15 · age 1 · sin θ, cos θ] (RU 마다 따로). 미래 스텝 각도는 지금 값 유지(`hold`) — 대시보드가 미래 각도를 모르니까. 바꿔 보고 싶은 곳: `beam/beam_features.py` (특징 식) · `train_GRU_beam.py` (`BeamGRU`)
- 고쳐도 되고 갈아엎어도 된다. 대시보드와 맞추려면 `hj_common.NumpyPredictor` 가 읽는 매개변수 이름(`rnn.*` · `out_proj.*` · `init_tok`)과 config `beam_feat_dim` 만 지키면 된다

## B. 빔 온 뒤 (12-01 ~ )

### B1. 첫날 점검 (전원, `code/README.md` 'FR3 날 순서')
config 에 UD 3대 · BBox 6대 SN → `python -m tmytek.tmytek_setup` (잠금 확인) → `tools/level_budget.py` → `tools/fr3_check.py` (`--isolate` · `--sweep` → backoff) → `tools/calib_ru.py --write` → `phi_sign` 확인 (`beam_tracker --fixed-deg ±`)

### B2. 위치 기반 빔 추적 데모 (카톡 1번)
```bash
bash run_fr3_scenario.sh              # 위치 → 빔 추적 (facing 이동)
BEAM=fixed bash run_fr3_scenario.sh   # 비교: 빔 0° 고정
```
볼 것: 추적 대 고정의 수신 세기 · `logs/beam_*.csv` 의 `apply_ms` (실제 빔 전환 시간) → 길면 config `beam.rate_hz` 를 낮춘다

### B3. 빔 켠 데이터로 각도 입력 GRU 판정 (카톡 2번, 승환)
1. 빔 추적을 **켠 채로** facing run 을 여러 번 모은다 (`logs/YYYYMMDD/*_gc_3x310_facing_*`). `beam_tracker` 로그(`logs/beam_*.csv`)가 같은 시간대에 있어야 실제 각도가 붙는다
2. 데이터 만들기 — run 폴더를 직접 나눈다
   ```bash
   python tools/build_beam_dataset.py --train <run 들> --validation <run> --test <run> --scale 0 --out data_ready_fr3
   ```
   출력의 `각도 beam_log` 가 떠야 실제 적용 각도다 (`geometry` 면 로그를 못 찾은 것)
3. `python train_GRU_beam.py --data data_ready_fr3` 대 `--no-angle` → test NMSE 비교 (seed 2~3개로 흔들림도 본다)
4. 이득이 있으면 그 모델로 대시보드 (`--predictor-model checkpoints_beam/<이름>.pt`)

### B4. 위치 오차 다시 (카톡 3번)
A1 결과가 '주의' 이상이면: 데모 run 을 짧게 끊어 자주 출발 자리로 되돌리거나, `beam_tracker` 의 `beam.lead_s` · `step_deg` 를 조정
